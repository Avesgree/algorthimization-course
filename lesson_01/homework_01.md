## Разбор сервиса Telegram

* Действие 1: Отправка текстового сообщения в чат
    * Что уходит: ID чата, текст сообщения, таймштамп, токен авторизации пользователя.
    * Что проверяет сервер: Существует ли чат, состоит ли в нём отправитель, не заблокирован ли он, не пустой ли текст.
    * Куда сохраняется: В базу данных сообщений (связанную с этим ID чата).
    * Что возвращается: Статус доставки (ID нового сообщения, точное время сервера), push-уведомление получателю.
* Действие 2: Удаление сообщения для всех
    * Что уходит: ID сообщения, ID чата, флаг «удалить для всех».
    * Что проверяет сервер: Является ли пользователь автором сообщения (или админом чата), прошло ли допустимое время для удаления.
    * Куда сохраняется: Из базы данных удаляется запись (или ей присваивается статус «удалено»).
    * Что возвращается: Подтверждение успешного удаления (код 200 OK), сигнал для приложения получателя стереть сообщение с экрана.
* Действие 3: Поиск пользователя по @username
    * Что уходит: Строка с поисковым запросом (текст после знака @).
    * Что проверяет сервер: Длину запроса (обычно от 5 символов), отсутствие запрещённых знаков.
    * Куда сохраняется: Никуда не сохраняется (это поисковый запрос к кэшу или базе данных пользователей).
    * Что возвращается: Список найденных профилей (ID, имя, аватар, @username).
## Место для отказа (на примере отправки сообщения)
* Пропала сеть посередине: Сообщение зависает со значком «часики». Приложение сохраняет его в локальную базу (кэш смартфона) и пытается отправить снова при возобновлении связи.
* Двойное нажатие на кнопку: Благодаря встроенному уникальному ID (клиентскому хэндлу) сообщения на стороне приложения, сервер понимает, что это дубликат, игнорирует второй запрос и не отправляет сообщение дважды.
* Пустое поле: Кнопка отправки в интерфейсе становится неактивной. Если отправить пустой запрос программно, сервер вернет ошибку валидации данных (400 Bad Request).
